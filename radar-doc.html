一、定位

一句话：全球重大事件发生后，锋睿舆情雷达帮金融机构看清楚它往哪传导、影响哪些标的、哪些信号值得盯，并且每一次推演都留档复盘，用真实走势检验。

同一套引擎，两种用法：

市场雷达主动监控
谁定义对象锋睿（全球重大事件库）客户自主添加
监控范围全球宏观、行业、龙头公司、关键人物自选股票池、行业、人物、关键词、自家机构、发债主体、竞品
典型产出重大事件专题、传导图、全球日报、榜单个性化预警、持仓影响清单、自身声誉风险报告

核心骨架：采集 → 归并 → 分级 → 传导 → 局势推演 → 推演复盘。

二、产品结构：市场雷达 + 主动监控

两条线共用同一套数据、知识图谱和分析引擎，区别在于"谁决定盯什么"。

对比对象他们擅长锋睿的差异

主动监控怎么添加（5 步）：

  1. 选对象类型：公司 / 行业 / 人物 / 关键词 / 自家机构 / 发债主体
  2. 输入或批量导入：股票代码、公司名、人名、关键词；自动对齐 A/H/美/韩/日多地代码和多语言名称
  3. 设阈值：只推红色 / 红+黄 / 全部；指定关心的事件类型
  4. 选语言与市场：默认全部，可只选部分
  5. 选推送渠道：企业微信 / 飞书 / 邮件 / API

自动扩展：添加一家公司时，系统从知识图谱推荐它的核心供应商、客户、竞争对手和关键人物，一键加入。

多语言不只是翻译：同一事件在不同语言媒体里的态度差异本身就是信号。"跨语言情绪差"指标——美国偏负面、韩国关注供应链、中文关注国产替代，差距越大，越可能存在定价分歧。

五、事件类型与分级标准

每条事件打三个标签：事件类型、事实分级、影响分级。

事件类型（八类）：高管与治理 / 业绩 / 监管与司法 / 股权与资本 / 政策 / 地缘与黑天鹅 / 舆情发酵 / 信用。

事实分级（四档）：已确认（公告、官方表态）/ 媒体报道（权威媒体）/ 未证实或传闻 / 已辟谣。

影响分级（红黄绿）：先由模型按事件类型、公司规模、传播速度初判，再用行情校准——事件后 1 天、5 天的超额收益。分级与实际市场反应不一致时，自动提示人工复核，并沉淀为下一次分级的参考。

社交舆情去噪：按账号可信度加权，识别水军和刷单，不只看声量。

六、重大主题传导模型

单点事件按五层递推，第六步"推演复盘"把结果回写到分级规则和传导图谱，形成闭环：

① 事件本体（事实分级：已确认/媒体报道/传闻不实）
   ↓
② 直接冲击（目标公司：股价、估值、预期）
   ↓
③ 产业链传导（上游供应商/下游客户/竞争对手/替代）
   ↓
④ 板块与市场传导（板块联动、资金流、市场情绪）+ 政策通道 + 多语言情绪差
   ↓
⑤ 情景推演（几种走向 + 概率 + 验证节点）
   ↓
⑥ 推演复盘（到期对账，回写规则）

每条传导边标"实线（已观察到）/ 虚线（待验证）"。点击任一节点，看影响说明、信号和原文来源。

七、回测与推演复盘：方法可靠，持续可靠

区别：

历史回测推演复盘
做法用过去事件检验传导模型和分级规则事前锁定推演，到期与实际结果对照
何时用上线前、规则调整后上线后每一次局势推演
证明什么方法有效持续有效，且没有"事后诸葛亮"

复盘流程：

  1. 留档：每次情景推演记录情景、概率、验证节点和判断依据，写入后不可修改
  2. 跟踪：到达验证节点时自动提醒，拉取当时公告与行情
  3. 复盘：对照实际走向，标记命中 / 部分命中 / 未命中，写明偏差原因
  4. 沉淀：结果反哺分级规则和传导图谱，累积为"推演命中率"
对客户的说法："回测证明方法可靠，复盘证明持续可靠。" 命中率长期积累后，就是最有说服力的销售材料。

命中率分母口径（定死）：只统计"有到期日且已到期"的推演；命中=1、部分命中=0.5、未命中=0；未到期只展示、不纳入。

八、新功能：主动监控 × 传导提醒

机制：客户在主动监控添加的对象（公司、行业、人物、关键词、大宗商品敞口），在知识图谱中即是一个实体节点。任何重大事件生成传导图时，只要图里有一条边指向该节点，就触发提醒。

实线 / 虚线，提醒语义必须分开：

传导边含义提醒语义紧急度
实线事件已影响该对象（有行情/公告证据）"这件事已经动了你的敞口"强提醒，立即
虚线事件可能传导到该对象（推演，待验证）"这件事可能传导到你的敞口，建议盯紧"预警级，附验证节点

价值在"推理"而非"匹配"：普通关键词监控抓不到"一条没提黄金的新闻"；传导提醒能。例：美联储放鹰的新闻全文没有"黄金"二字，但传导图推理出"加息预期 → 美元走强 → 实际利率上行 → 黄金承压（虚线）"，于是提醒客户。

提醒文案模板：

【传导提醒】"{事件标题}"
→ 可能传导到您监控的「黄金」（虚线·待验证）
→ 方向：利空 / 利多
→ 传导链：加息预期 → 美元走强 → 实际利率上行 → 黄金承压
→ 验证节点：下次议息会议（日期）
→ 来源：原文链接

闭环：主动监控（加对象）→ 传导图（虚线指向对象）→ 提醒 → 验证节点 → 到期复盘对账 → 命中率累积。

九、新客户需求：敞口情报精选

客户原话："结合我们大的敞口，比如原油、黄金，找到市场影响大的新闻……我们不交易，不一定要快，但能推荐出关于这个产品的最重要的新闻。"

理解：不是"新闻预警"，是"敞口情报精选"。他不缺信息，缺"哪几条真正影响我的敞口、为什么"。

交易向敞口向
核心指标快（分钟级）准（重要性排序）
锚点市场/事件我的敞口
输出预警 + 专题每日精选 3–5 条 + 为什么
用户交易员、投研套保、资产配置、司库、实物贸易

产品形态："敞口精选日报"——每天开盘前，围绕客户登记的敞口，推 3–5 条影响最大的事件，每条附：事实分级 + 影响方向 + 传导链 + 一句"为什么重要"。

"不交易"是优势不是限制：不追求快，就有时间做"影响大不大"的深度判断。

十二、治理与合规

  • 不构成投资建议：只回答"影响哪些标的、影响多大、盯哪些信号"，不给买卖建议。
  • 人工复核：红色事件和情景概率发布前由分析师确认；投顾内容经合规审核。
  • 数据不出域：L3 客户数据只在私有化环境处理，支持信创环境与已备案大模型。
  • 审计留痕：每条结论可追溯到原文链接；推演留档不可修改。
  • 敏感信息：未证实传闻必须标注事实分级，不单独推送；隐私内容只保留与市场相关部分。
  • 跨境数据：海外舆情采集与境内客户数据分开存放，按数据出境规定处理。

十三、对话入口："问雷达"

在日报、专题、传导图旁放对话框，用户自然语言追问。回答只基于已采集、已分级的数据，每句话带来源和事实分级。

固定结构：一句结论 → 事实分级 → 传导链条 → 待验证节点 → 原文来源链接。

边界：不回答"该买还是该卖"；没有来源支撑的问题直接说"雷达暂无数据"，不猜；所有对话留痕可审计。

问题类型：事件问答 / 传导追问 / 情景假设 / 事实核查 / 跨语言对比 / 推演复盘 / 一键加入监控。

模型接入结论：

  1. 接入 DeepSeek 等模型，走多模型路由（商业/开源/境内自主可控切换），DeepSeek 开源版可私有化部署，满足信创与合规。
  2. "问雷达"是 RAG，不是自由对话；约束须通过检索层 + 提示词硬性执行。
  3. 采集不用大模型（关键边界）：
环节用什么用不用模型
采集/抓取爬虫、API、订阅源❌ 不用
理解/处理（翻译、摘要、实体识别、分级、情绪打分）模型✅ 用
研判/推演模型 + 分析师✅ 用 + 人
把关/发布合规、人工确认❌ 人
对外口径："机器采集 + 模型研判"，不说"用大模型抓舆情"。

产品回答的问题环节主要用户

  ↓ 复盘回写

为什么三个一起讲：单卖雷达是"资讯工具"、单卖 Agenta 是"投研插件"，三个一起是"从感知到执行的完整投研操作系统"——这是融资叙事和销售定位的分水岭。

落地顺序：先雷达（能演示、决策链短）→ 再 Agenta（事件带动估值需求）→ 后 Quant72（有持仓后自然要验证）。

二十一、关于命中：我们不卖预言，卖可验证

历史不会重演，但会押韵（History doesn't repeat itself, but it often rhymes）。

周期理论（如康波）的方向判断常有解释力，但时点与幅度判断经常失准。这恰恰说明：结构会重复，时点和幅度每次都不同。

因此，产品不卖"预测"，卖"推演框架"：

卖预测（危险）卖框架（稳）
客户怎么理解"你预测的事发生了吗？""该看见的风险，提前让我看见了吗？"
核心动作猜中唯一未来把不确定性结构化，写清验证节点
命中率含义神不神有没有"事后诸葛亮"

命中率的准确定义 = "风险提前看见率"，而非"预言准确率"。

三条口径（钉死，防止反噬）：

  1. 命中率分母只算"有到期日且已到期"的推演；未到期的只展示、不纳入。
  2. 虚线推演未发生时，复盘反而证明"我们诚实区分了已发生与待验证"，而非事后诸葛亮。
  3. 历史可比只比"结构相似"的同类事件（同国同监管、同类型），不比"看起来像"，否则是拿历史硬套未来。
一句话：别担心命中，要担心的是"承诺命中"。 一个情报系统最值钱的，不是永不犯错，是错了认账、事事有据。我们把账本做出来，就已经赢了。

附：五条升级意见汇总

  1. 演示选例：韩股崩盘讲"可对账"（熔断/资金流/政府应对已兑现），黄仁勋讲"深度传导"。
  2. 跨语言情绪差口径：同一提示词、同一打分标尺，用"相对自身历史"跨语言比较。
  3. 命中率分母：只统计已到期推演；命中=1、部分=0.5、未命中=0。
  4. 传闻可信度：四档事实分级不变，给"未证实"加信源数量/可信度权重。
  5. SOP 转 SLA：把时间线包装成对客户的 SLA 承诺。
